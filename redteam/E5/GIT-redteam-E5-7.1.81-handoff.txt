NÁLEZY A OPRAVY
E5-01 / HIGH: návrat po odchodu se v zamčeném stavu nevyhodnocoval,
protože isTestRunning vylučoval LOCKED. Opakovaný odchod přepisoval
první čas. Nově se sleduje aktivní pokus i za zámkem; LEFT_AT se
nastaví pouze při prvním odchodu a vrácení zapíše awayMs/severity.
První odchod je součástí místního sealed auditu i přes reload.
Čas pokusu se tím neprodlužuje a klientský čas není důkaz původu.

E5-02 / HIGH: běžný setResp zapisoval i po uzamčení nebo odevzdání.
Nově vyžaduje skutečně běžící odemčený pokus. #test je za zámkem
inert a skrytý pro accessibility strom; dialog má název a přijímá
fokus. Unlock inert odstraní a zachová odpovědi, historii i deadline.
Nativní klávesnice nemůže za zámkem upravovat test. Přímá editace
RAM/globalů, DOM či listenerů vlastníkem klienta zůstává možná.

E5-03 / HIGH: před reloadem nebyl beforeunload vždy důvodem zámku
a nový monitor nuloval dřívější split-window měření. Nově strict
beforeunload/pagehide zamkne pokus; obnovený strict pokus je vždy
zamčený, včetně stavu dříve úspěšně odemčeného kódem třídy.
Původní attempt ID, odpovědi a deadline se zachovají; další běžný
unlock dovolí pokračování bez nového pokusu nebo nového časového limitu.
Split total/small/run a LEFT_AT se ukládají a obnovují. Restart
monitoru je nenuluje. Flush uloží čekající snapshot před návratem;
dřívější flush pouze rušil jeho timer. Snapshot se před zařazením
do fronty kopíruje, takže pozdější běžná změna nezmění starší zápis.
Guard-only unsigned shadow může obnovit konzervativní zámek/audit;
změna odpovědí, identity, žolíku či oslabení deadline/zámku nadále
vyvolává integrity blokaci. Podepsaný rollback má původní E4 limit.

E5-04 / MEDIUM: fullscreen API nemělo obsluhu odmítnutého Promise
a opuštění fullscreen se nezachytávalo. Nově po skutečném vstupu
nativní exit zapisuje fullscreen-left a v strict režimu zamyká.
Odmítnuté/nedostupné API zobrazí modal a audit; není unhandled error.
Fullscreen není nový povinný startovní gate na nepodporovaném zařízení.
Standardní režim událost eviduje bez strict blokace. API nemůže
dokázat, že student nemá jinou obrazovku, aplikaci nebo další zařízení.

E5-05 / HIGH: správný odemykací kód mohl po asynchronním PBKDF2
odemknout stránku, která mezitím znovu odešla. Nově se porovnává
guard epoch z počátku s koncem ověřování, aktuální visibility a
integrity stav. Blur epoch zvýší ihned, i při už zamčeném pokusu.
Další odchod během ověřování zámek ponechá; UNLOCK_BUSY se vždy
uvolní v finally a nevznikne falešný recovery-unlock záznam.
Kód třídy nemá teacher/admin, reset ani retry pravomoc a jeho
klientský hash neslouží jako bezpečnostní autentizace.

E5-06 / MEDIUM: history, freeze/resume a cache restore neměly
samostatnou obsluhu. Popstate a freeze nově zapisují odchod a
strict zámek; resume zapíše návrat a obnoví původní časovač.
Persisted pageshow zamkne UI před asynchronním čtením, znovu získá
tab lock, kontroluje outbox/submitted guard a načte aktuální sealed
stav. Starší RAM neobnoví předchozí odpovědi přes novější úložiště;
neplatná obnova zůstane blokovaná. Platný standardní režim uvolní
dočasný reconciliation lock; strict ponechá zámek. Deadline může být jen konzervativně
zkrácen. document.wasDiscarded se eviduje, pokud jej browser poskytne.
Nativní BFCache eligibility a skutečné OS discard nejsou doloženy.

E5-07 / MEDIUM: paste měl pouze audit velkého textu. V strict testu
se běžný paste/drop/insertFromPaste/insertFromDrop blokuje a loguje.
Za zámkem se v testu blokuje beforeinput/keydown. Standardní režim
ponechá běžný paste a zapíše pouze délku/počet slov u velkého vložení.
Obsah schránky se do auditu neukládá. Clipboard/drop mimo oblast
testu, například identita před zahájením, není tímto gate omezený.
Copy/cut, screenshoty ani druhé zařízení nejsou touto změnou blokované.

E5-08 / AUDIT: nové guard události jsou ve verifieru přehledné
