# Sprint 08 — proposed safe release runbook

This is a proposal, not authorization to release. `candidate` can trigger promotion and must remain untouched until the owner issues an explicit release GO.

## Entry conditions

1. Independently approve and merge the dedicated EOL/trust-byte-contract remediation without changing the reviewed anchor digest.
2. Independently review the eight semantic AI-boundary files and approve a dedicated assurance evidence refresh.
3. Resolve or explicitly disposition every B05 failure with new negative controls.
4. Produce fresh foundation evidence on the exact candidate SHA; GARP foundation must be 11/11 PASS.
5. Complete Linux and Windows CI with identical declared inventory. No skipped security scenario may be counted as PASS.
6. Complete physical iPad/iPadOS, required mobile/tablet, AI Studio, live Google Forms/Sheets/MailApp and authorized GitHub Pages staging tests.

5. Confirm no real student data, access codes, private verifier or private key is in Git or build artifacts.
6. Perform the separately authorized version/release identity update and regenerate SBOM/evidence from that exact SHA.
7. Run T01–T135; T110 remains DEFERRED unless the server phase is separately authorized.

## Promotion gates

All of the following must be PASS on the exact candidate SHA: F0 on Windows and Linux, AI assurance, GARP 2.7 static and foundation, complete CI, build, source/browser security gates, newly generated instant/secure/verifier artifacts, live Forms workflow and authorized physical-device matrix. Any FAIL, missing evidence, SHA mismatch or unreviewed generated artifact is a stop condition.

## Controlled staging

Use a non-production URL and synthetic identities only. Verify cache/republication behavior, active-attempt continuity, recovery, Forms submission/import, verifier chronology/CSV/PDF and rollback. Do not overwrite an active published student test.

## Production release

Production requires a separate explicit owner instruction after independent GO. Record candidate SHA, artifact hashes, reviewer approvals, deployment timestamp and rollback target. Do not force-push. Immediately stop and roll back if integrity metadata, recovery, submission, scoring or verifier parity differs from the approved staging evidence.

## Rollback

Rollback is to the last independently approved production artifact and commit, not to an unreviewed local tree. Preserve incident evidence and submitted results; never delete or rewrite student attempts to make the release appear healthy.
